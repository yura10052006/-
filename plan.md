## 1. Архітектура в цілому (architecture overview)

Два компоненти + зовнішні API:

```
┌─────────────────────────┐         HTTPS multipart          ┌──────────────────────────┐
│  ANDROID (Kotlin)        │  ── аудіо (WAV 8кГц) ──────────► │  PYTHON BACKEND (FastAPI)│
│  «тонкий клієнт»          │                                  │  «мозок»                  │
│                          │  ◄── JSON {recognized, reply} ── │                          │
│  • push-to-talk кнопка   │                                  │  1. STT (Whisper)        │
│  • запис з HFP-мікрофона │                                  │  2. Claude + tool use    │
│  • системний TTS (вихід) │                                  │  3. Todoist (create_task)│
│  • індикація стану        │                                  └───────────┬──────────────┘
└─────────────────────────┘                                              │
                                                        ┌─────────────────┼─────────────────┐
                                                        ▼                 ▼                 ▼
                                                  OpenAI Whisper   Anthropic API      Todoist API
                                                   (STT, uk)       (/v1/messages)     (REST v2)
```

**Ключова ідея розподілу (separation of concerns — розділення відповідальностей):**
весь незнайомий тобі код (цикл tool use, виклики LLM) — у Python, де ти вдома.
Android робить лише «залізні» речі, які *мусять* бути на пристрої: мікрофон, динамік, кнопка.

Терміни:
- **client** (клієнт) — Android-застосунок, що надсилає запити.
- **backend** (бекенд) — серверна частина, приймає запити, робить логіку.
- **endpoint** (ендпоінт) — конкретна URL-адреса на бекенді, напр. `POST /command`.
- **multipart** — спосіб надіслати файл (аудіо) в HTTP-запиті.

## 2. Контракт між клієнтом і бекендом (API contract)

Це найважливіший інтерфейс — фіксуємо його першим, щоб клієнт і бекенд можна було робити паралельно й незалежно.

### 2.1. `POST /command`
Основний і єдиний потрібний для MVP ендпоінт.

**Запит (request):**
- Метод: `POST`, `Content-Type: multipart/form-data`
- Заголовок `X-App-Token: <секрет>` — простий спільний секрет (shared secret), щоб чужі не витрачали твої API-кредити.
- Поле `audio`: файл `WAV`, PCM 16-bit, **8000 Гц, моно** (навмисне 8 кГц — тестуємо якість окулярів, NFR-2).
- (Опційно) поле `locale`: `"uk-UA"`.

**Відповідь (response), `200 OK`, `application/json`:**
```json
{
  "recognized_text": "додай задачу купити каву",
  "reply_text": "Додав задачу: купити каву",
  "action": {
    "type": "create_task",
    "ok": true,
    "task": { "id": "789", "content": "купити каву", "url": "https://todoist.com/..." }
  },
  "timings_ms": { "stt": 1200, "llm": 1500, "tool": 300, "total": 3200 }
}
```
- `recognized_text` — щоб клієнт показав, що почув STT (FR-11).
- `reply_text` — це клієнт озвучить системним TTS (FR-7/FR-8).
- `action` — що реально зроблено (може бути `null`, якщо Claude лише відповів без інструмента).
- `timings_ms` — для метрик латентності (§8 spec).

**Помилки:** завжди `200` з полем `reply_text`, придатним для озвучування («Не почув, повтори», «Сервіс недоступний»), + технічне поле `error`. Так клієнт лишається дурним: що прийшло в `reply_text` — те й каже. HTTP-коди 4xx/5xx — лише для геть фатального (поганий токен).

### 2.2. `GET /health`
Проста перевірка, що бекенд живий (для дебагу й моніторингу хостингу). Повертає `{"status":"ok"}`.

## 3. Python-бекенд (детально)

### 3.1. Стек
- **FastAPI** — веб-фреймворк (framework — каркас), async, мінімум коду, автодокументація.
- **uvicorn** — ASGI-сервер (запускає FastAPI).
- **anthropic** — офіційний SDK для Claude.
- **openai** — офіційний SDK (використаємо лише `audio.transcriptions` для Whisper).
- **httpx** — HTTP-клієнт для Todoist REST.
- **pydantic** — валідація моделей запиту/відповіді (вбудовано у FastAPI).
- **python-dotenv** — читання `.env`.

### 3.2. Структура тек
```
backend/
  app/
    main.py            # FastAPI: маршрути /command, /health; склеює все
    config.py          # читання ключів з .env, налаштування
    stt.py             # transcribe(audio_bytes) -> str   (Whisper)
    agent.py           # run_agent(user_text) -> AgentResult   (цикл tool use)
    tools/
      __init__.py      # реєстр інструментів (tool schema для Claude)
      todoist.py       # create_task(content, due_string?) -> dict
    models.py          # pydantic-моделі відповіді
  requirements.txt
  .env.example
  README.md            # як запустити локально й задеплоїти
```

### 3.3. `stt.py` — розпізнавання
- Приймає байти WAV, віддає в OpenAI `audio.transcriptions.create(model="whisper-1", language="uk", file=...)`.
- Повертає рядок тексту.
- Абстракція: інтерфейс `Transcriber` з методом `transcribe(bytes) -> str`, реалізація `WhisperTranscriber`. Так пізніше підмінимо на локальний Whisper/Google STT без правок решти коду (закладено в D-2).

### 3.4. `agent.py` — цикл tool use (серце системи)
Класичний цикл (loop) Anthropic Messages API:
1. Формуємо `system`-промпт: «Ти голосовий асистент. Користувач говорить українською. Якщо він просить створити задачу — виклич інструмент `create_task`. Відповідай КОРОТКО однією фразою українською, придатною для озвучування вголос.»
2. Викликаємо `messages.create(model, tools=[create_task_schema], messages=[user_text])`.
3. Якщо `stop_reason == "tool_use"` — виконуємо відповідний Python-інструмент (`tools/todoist.py`), додаємо `tool_result` у діалог, викликаємо `messages.create` ще раз.
4. Отримуємо фінальний текст → це `reply_text`.
- **Модель:** `claude-haiku-4-5-20251001` (Haiku 4.5) — швидко й дешево, для «створи задачу» якості вистачає. Резерв — `claude-sonnet-5`, якщо Haiku плутатиме.
- Повертає `AgentResult{ reply_text, action }`.
- **Reuse:** структура один-в-один як у твого Instagram-агента (той самий патерн tool use), тому код тобі знайомий.

### 3.5. `tools/todoist.py` — реальний інструмент
- `create_task(content: str, due_string: str | None) -> dict`
- `POST https://api.todoist.com/rest/v2/tasks`, заголовок `Authorization: Bearer <TODOIST_TOKEN>`, тіло `{"content": ..., "due_string": ...}`.
- `due_string` — Todoist сам парсить природну мову дат («завтра», «сьогодні о 18:00»), тож дати майже безкоштовні.
- Повертає `{id, content, url, ok}`.
- **Tool schema** (опис інструмента для Claude) — JSON з полями `content` (обов'язкове) і `due_string` (опційне), із описами українською/англійською.

### 3.6. Конфіг і секрети
`.env` (не в git, є `.env.example`):
```
ANTHROPIC_API_KEY=...
OPENAI_API_KEY=...
TODOIST_TOKEN=...
APP_SHARED_TOKEN=...        # секрет для X-App-Token
CLAUDE_MODEL=claude-haiku-4-5-20251001
```

### 3.7. Хостинг (де запустити бекенд)
⚠️ **Чесно про твій досвід:** Supabase Edge Functions і Netlify Functions — це **JS/TS (Deno/Node)**, не Python. Наш бекенд — Python (щоб перевикористати tool use). Тому для нього раджу Python-native хостинг:
- **Railway** (рекомендую) — найпростіший деплой Python з git, є безкоштовний старт. `Procfile`/автодетект.
- **Render** — теж просто, є free tier (засинає при простої — для особистого ок).
- **Fly.io** — трохи більше налаштувань, зате швидко й близько.
- **Власний VPS** — якщо вже є.
- Локально для розробки — просто `uvicorn`, а телефон ходить на твій IP у Wi-Fi (або через `ngrok` — тимчасовий публічний тунель).
- **Рекомендація MVP:** розробляй локально (`uvicorn` + `ngrok`), для «щоденного носіння» — задеплой на Railway/Render. Остаточний вибір за тобою; на код бекенда він майже не впливає.

## 4. Android-клієнт (детально)

### 4.1. Стек
- **Kotlin** + **Jetpack Compose** (сучасний UI-фреймворк, декларативний — уже був у старому каркасі).
- **OkHttp** — один multipart-POST на бекенд (Retrofit — надлишок для одного ендпоінта).
- **AudioRecord** (Android SDK) — запис PCM, повний контроль над 8 кГц моно.
- **TextToSpeech** (Android SDK) — системне озвучування.
- **Coroutines** — асинхронність без блокування UI.
- `minSdk` 26 (Android 8), `targetSdk` актуальний. Redmi 13 Pro (Android 14+) підходить із запасом.

### 4.2. Структура
```
android/
  app/src/main/java/com/voiceassistant/
    MainActivity.kt          # хост Compose
    ui/
      VoiceScreen.kt         # єдиний екран: кнопка + індикатор стану + розпізнаний текст
      VoiceViewModel.kt      # стейт-машина, оркеструє запис→мережа→TTS
    audio/
      BluetoothScoManager.kt # увімкнути/вимкнути SCO (HFP-мікрофон гарнітури)
      AudioRecorder.kt       # AudioRecord → WAV-байти (8кГц, моно, 16-bit)
      Tts.kt                 # обгортка TextToSpeech (uk-UA)
    net/
      BackendClient.kt       # OkHttp: POST /command (multipart), парсинг JSON
    Config.kt                # BASE_URL бекенда, APP_SHARED_TOKEN
```

### 4.3. Стейт-машина екрана (FR-9)
```
IDLE ──(натиснув)──► RECORDING ──(відпустив)──► UPLOADING ──► THINKING* ──► SPEAKING ──► IDLE
                                                     │                          
                                                     └──(будь-яка помилка)──► ERROR ──► IDLE
```
(*THINKING/UPLOADING для клієнта — один стан «чекаю бекенд»; бекенд сам ділить на STT/LLM/tool.)
Кожен стан має видимий підпис і колір. `ERROR` теж озвучується.

### 4.4. Захоплення HFP-мікрофона (найтонше місце) ⚠️
Це технічно найризикованіша частина — розписую чесно.
- Щоб писати з **мікрофона Bluetooth-гарнітури** (а не телефона), треба підняти **SCO** (Synchronous Connection-Oriented — канал HFP для голосу):
  - Android ≤ 11: `AudioManager.startBluetoothSco()` + `setBluetoothScoOn(true)` (нині deprecated — застарілі).
  - Android 12+ (наш випадок): `AudioManager.setCommunicationDevice(TYPE_BLUETOOTH_SCO)`.
- Джерело запису: `MediaRecorder.AudioSource.VOICE_COMMUNICATION` (застосовує ехо/шумоподавлення, ближче до сценарію окулярів).
- SCO дає **8 кГц** (narrowband) або 16 кГц (wideband) — тобто реальний BT-тест *і є* тестом 8 кГц. Ідеально збігається з NFR-2.
- **Тонкість вивід↔вхід:** поки SCO активний, звук іде вузькосмуговим HFP. TTS-відповідь хочемо чути якісно через **A2DP**. Тому послідовність: `підняти SCO → записати → опустити SCO → (пристрій перемикається на A2DP) → озвучити TTS`. Перемикання профілю додає ~0.5–1 с — закладаємо в бюджет латентності й у стейт-машину.
- **Fallback (запасний шлях):** якщо BT-навушників ще нема (відкрите питання §11.1 spec) — пишемо з мікрофона телефона, але **примусово 8 кГц моно** в `AudioRecord`, щоб чесно тестувати STT на низькій якості (без beamforming-артефактів окулярів, але бітрейт той самий).

### 4.5. TTS (озвучування, FR-8)
- `TextToSpeech`, `setLanguage(Locale("uk","UA"))`.
- **Ризик:** український голос є не на всіх пристроях/движках. **Перша задача tasks.md** — перевірити на Redmi 13 Pro (`isLanguageAvailable`). Якщо нема — варіанти: доставити Google TTS uk-голос, або тимчасово хмарний TTS (виходить за MVP, але тримаємо в резерві).
- Вихід за замовчуванням іде на активний A2DP (навушники/окуляри).

### 4.6. Дозволи (permissions)
`AndroidManifest.xml`: `RECORD_AUDIO`, `BLUETOOTH_CONNECT` (API 31+), `INTERNET`, `MODIFY_AUDIO_SETTINGS`.
Runtime-запит `RECORD_AUDIO` + `BLUETOOTH_CONNECT` на першому старті. ⚠️ MIUI/HyperOS іноді ховає ці дозволи глибше — у README згадаємо ручну видачу.

## 5. Наскрізний сценарій (end-to-end flow)

1. Тап-і-утримання кнопки → `BluetoothScoManager.start()` → `AudioRecorder.start()` (8кГц/моно).
2. Відпустив → зупинка запису → WAV-байти в пам'яті → `BluetoothScoManager.stop()`.
3. `BackendClient.postCommand(wav)` → `POST /command` з `X-App-Token`.
4. Бекенд: `stt.transcribe()` → `agent.run_agent()` (Claude → можливо `create_task` у Todoist) → JSON.
5. Клієнт показує `recognized_text`, потім `Tts.speak(reply_text)`.
6. Стан → `IDLE`. Задача вже в Todoist (видно в застосунку Todoist).

**Бюджет латентності (чесна оцінка, NFR-1):**
| Крок | ~час |
|---|---|
| upload WAV (~80 КБ) | 0.2 с |
| Whisper STT | 1–2 с |
| Claude Haiku (2 виклики: tool + фінал) | 1–2 с |
| Todoist | 0.3 с |
| відповідь + перемикання SCO→A2DP + старт TTS | 1 с |
| **Разом** | **~4–6 с** |
Впритул до цілі 5 с. Якщо систематично > 8 с — оптимізуємо (напр. один виклик Claude без tool, або стрімінг STT). Це вже поза MVP.

## 6. Обробка помилок (error handling)
- **Немає мережі / бекенд не відповідає:** клієнт озвучує «Немає зв'язку з сервером», стан ERROR.
- **STT нічого не розпізнав / порожньо:** бекенд повертає `reply_text="Не почув, повтори будь ласка"`.
- **Claude/Todoist впав:** бекенд ловить виняток, `reply_text="Не вдалося створити задачу, спробуй ще раз"`, `action.ok=false`.
- **TTS без укр-голосу:** клієнт показує текст на екрані + короткий «біп», лог у README-нотатці.
- Принцип: **застосунок ніколи не крешить** (FR-10); будь-яка гілка веде в зрозумілий стан.

## 7. Безпека (security)
- Ключі (Anthropic/OpenAI/Todoist) — лише на бекенді в `.env`, поза git (`.gitignore`).
- `X-App-Token` — простий спільний секрет клієнт↔бекенд, щоб чужі не викликали твій ендпоінт і не палили кредити. Не «справжня» автентифікація, але для особистого прототипу достатньо.
- HTTPS обов'язково на проді (Railway/Render дають безкоштовно). Локально — http у своєму Wi-Fi або ngrok (https).
- Жодних персональних даних не зберігаємо; аудіо не пишемо на диск бекенда (обробили в пам'яті — відкинули).
