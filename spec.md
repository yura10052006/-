# spec.md — Трек A: голосовий асистент на Bluetooth (прототип гіпотези)

> **Статус:** чернетка на затвердження. Код не пишемо, поки цей spec не погоджено.
> **Методологія:** SDD (Spec-Driven Development — розробка, керована специфікацією).
> **Дата:** 2026-07-24

---

## 0. Навіщо цей документ

Це `spec` (specification — специфікація, опис *що* робимо і *навіщо*, без *як*).
`Як` буде в `plan.md`. Конкретні кроки — у `tasks.md`.

Мета треку A — **не побудувати продукт**, а **перевірити одну гіпотезу**:

> «Мені особисто зручно й швидше давати задачі голосом, ніж руками, — настільки, щоб мало сенс купувати окуляри за ~20 000 грн.»

Усе, що не служить перевірці цієї гіпотези, — поза межами цього треку.

---

## 1. Гіпотеза і критерій успіху

**Гіпотеза (hypothesis):** голосовий цикл «сказав → зробилось → почув підтвердження» настільки зручний, що я буду ним користуватись регулярно.

**Як перевіряємо (validation):** користуюсь прототипом 1–2 тижні на щоденних дрібних задачах. Рішення про окуляри — на основі власного відчуття, не метрик. Метрики — вторинні (див. §8).

**Гіпотеза вважається спростованою, якщо:** латентність дратує, розпізнавання української стабільно помиляється, або я ловлю себе на тому, що все одно беру телефон у руки. Це нормальний і бажаний результат — він економить 20 000 грн.

---

## 2. Definition of Done (визначення готовності)

Прототип **готовий**, коли виконується весь ланцюг **на реальному пристрої (телефон + Bluetooth-навушники)**:

1. Натискаю кнопку в застосунку (push-to-talk — «натисни, щоб говорити»).
2. Кажу **українською**: «додай задачу купити каву».
3. Задача **реально з'являється** в підключеному зовнішньому сервісі (task-менеджер).
4. У навушник **звучить голосове підтвердження** українською (напр. «Додав задачу: купити каву»).
5. Весь цикл від кінця фрази до початку відповіді — суб'єктивно «не дратує» (орієнтир ≤ 5 секунд, див. §6).

Якщо всі 5 пунктів виконуються — трек A закрито, гіпотезу перевірено.

---

## 3. Пайплайн (pipeline — конвеєр обробки)

```
[Кнопка] → [Запис аудіо] → [STT] → [Claude + tool use] → [TTS] → [Звук у навушник]
   │            │             │            │                 │            │
push-to-talk  мікрофон    мова→текст   рішення+дія      текст→мова    A2DP/HFP
              (BT HFP)    (українська)  (Anthropic API)
```

Розшифровка англомовних термінів:

| Термін | Переклад / пояснення |
|---|---|
| **STT** (Speech-to-Text) | розпізнавання мови → текст |
| **TTS** (Text-to-Speech) | синтез мови ← текст (озвучування) |
| **tool use** | «використання інструментів» — Claude не просто відповідає текстом, а викликає задану функцію (напр. «створити задачу»), яку виконує наш код |
| **push-to-talk** | «натисни й говори» — запис іде лише поки/після натискання кнопки |
| **A2DP** | Bluetooth-профіль для якісного стерео-виводу (музика, TTS у вухо) |
| **HFP** (Hands-Free Profile) | Bluetooth-профіль двостороннього голосу; саме через нього йде мікрофон гарнітури, якість 8 кГц моно |

## 4. Межі (scope)

### 4.1. В межах (in scope)
- Нативний (native) Android-застосунок на Kotlin.
- Одна кнопка push-to-talk, мінімальний екран.
- Робота через звичайні Bluetooth-навушники з мікрофоном (окуляри пізніше підключаться так само — як звичайна гарнітура).
- Українська мова **на вході** (STT) — обов'язково.
- Українська мова **на виході** (TTS).
- **Рівно один** реальний tool use — створення задачі в зовнішньому сервісі.
- Сесійний запис: тригер → запис → закрити потік (не тримати стрім відкритим — економія батареї).

### 4.2. Поза межами (out of scope) — свідомо не робимо
- ❌ Окуляри Ray-Ban Meta та будь-що з Meta SDK / Device Access Toolkit (це треки B і C).
- ❌ Камера, сценарій «що я бачу».
- ❌ Кастомний голосовий тригер «просто заговорив» (недоступний технічно — тільки кнопка).
- ❌ Локальний Whisper, ElevenLabs — опційні покращення на потім, не в MVP.
- ❌ Кілька інструментів, складні діалоги, пам'ять між сесіями, історія.
- ❌ Публікація в стори, монетизація, мультикористувацькість, акаунти.
- ❌ iOS.
- ❌ Наявний у репозиторії каркас «Командний калькулятор зарплати» — це чужий проєкт (див. §9).

## 7. Ключові рішення на затвердження (decisions)

Це розвилки, де мені потрібне твоє «так» перед `plan.md`. Для кожної даю рекомендацію і чесний ризик.

### D-1. Архітектура: чистий Android чи Android + Python-бекенд?
- **Варіант A (рекомендую для MVP):** «товстий» Android-застосунок, який сам ходить в STT, Anthropic і сервіс задач. Найшвидше до результату, нема що хостити.
- **Варіант B:** тонкий Android + маленький Python-бекенд (перевикористати твій підхід tool use з Instagram-агента). Краще ховає ключі, легше міняти логіку, ближче до «серйозної» архітектури. Але треба десь хостити (Netlify Functions / Supabase Edge / власний сервер) і це +1 точка відмови.
- ⚠️ **Чесно:** твій стек-досвід (Python, tool use, SQLite) кричить за B. Але для перевірки *гіпотези зручності* архітектура значення не має — важить лише латентність і UX. Тому раджу **A на MVP**, з розрахунком легко винести логіку в B пізніше. Рішення за тобою.

### D-2. STT-провайдер (українська, стійкість до 8 кГц)
- **Рекомендую:** OpenAI Whisper API (`whisper-1`) — добре тримає українську і стійкий до шуму/низького бітрейту. Або **Google Cloud Speech-to-Text** (`uk-UA`), рідний для Android-екосистеми.
- ⚠️ **Чесно:** обидва — платні хмарні сервіси (суперечить «нічого платного»? — це pay-per-use копійки, не підписка). Безкоштовний варіант — вбудований Android `SpeechRecognizer`, але він **ненадійний для 8 кГц HFP** і залежить від Google-сервісів на пристрої. Пропоную закласти абстракцію STT (інтерфейс), MVP — на Whisper/Google, з можливістю замінити.

### D-3. TTS-провайдер
- **Рекомендую:** системний Android TTS (безкоштовний). Українська підтримується не на всіх пристроях однаково — треба перевірити на твоєму телефоні (це перша задача в `tasks.md`). ElevenLabs — опційно потім.
- ⚠️ **Чесно:** якщо на твоєму телефоні немає українського голосу в системному TTS — доведеться або ставити голосовий рушій, або одразу брати хмарний TTS. Це перевіримо емпірично.

### D-4. Куди «падає» задача — який сервіс task-менеджера?
Потрібен сервіс з простим API. Варіанти:
- **Todoist** — REST API, токен, дуже простий, ідеальний для «create_task». **Рекомендую.**
- **Google Tasks / Google Calendar** — є, але OAuth складніший.
- **Notion** — потужно, але API важчий для однієї задачі.
- **Локальний SQLite** — найпростіше, але задача «нікуди не летить», слабше доводить «Claude реально робить».
- ⚠️ Рекомендація: **Todoist** — найкоротший шлях до чесного Definition of Done (задача видима в реальному застосунку на телефоні).

### D-5. Куди діти наявний каркас у репозиторії? (див. §9)
- **Рекомендую:** видалити код «калькулятора зарплати» і почати Android-проєкт треку A з чистого каркаса на цій же гілці.
- Альтернатива: залишити в окремій теці. Раджу **видалити** — він тільки заважатиме.

### D-6. Ключ Anthropic API
- Треба, щоб ти згенерував ключ на console.anthropic.com і поклав у `.env` (не в git). У Варіанті A (§D-1) ключ живе на пристрої в debug-збірці — прийнятно для особистого прототипу, **неприйнятно для публікації** (але публікації й нема).

## 8. Метрики (вторинні, для власного відчуття)
Не критерій успіху, але корисно занотувати під час тесту:
- Середня латентність циклу (с).
- % команд, розпізнаних правильно з першого разу.
- Скільки разів за день реально скористався.
- Суб'єктивна оцінка 1–5 «чи хочу окуляри після цього».

## 9. Стан репозиторію (важливо)
Наразі в репозиторії лежить **непов'язаний** проєкт: Android-каркас «Командний калькулятор зарплати» (AI Studio, Gemini API). До голосового асистента відношення не має. Він потрапив сюди як шаблон. Що з ним робити — рішення **D-5**. До затвердження **нічого не видаляю і не чіпаю**.

## 10. Припущення (assumptions)
- У тебе є Android-телефон для запуску debug-збірки (не лише емулятор — Bluetooth-аудіо треба тестувати «в залізі»).
- Є Bluetooth-навушники з мікрофоном для чесного тесту HFP.
- Готовий завести платні pay-per-use ключі (Anthropic обов'язково; STT/TTS — залежно від D-2/D-3), витрати — центи на день тесту.
- Anthropic API доступний з України (перевіримо; за потреби — той самий проксі-підхід, що й для інших сервісів).
