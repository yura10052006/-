## 0. Навіщо цей документ

Це `spec` (specification — специфікація, опис *що* робимо і *навіщо*, без *як*).
`Як` буде в `plan.md`. Конкретні кроки — у `tasks.md`.

Мета треку A — **не побудувати продукт**, а **перевірити одну гіпотезу**:

> «Мені особисто зручно й швидше давати задачі голосом, ніж руками, — настільки, щоб мало сенс купувати окуляри за ~20 000 грн.»

Усе, що не служить перевірці цієї гіпотези, — поза межами цього треку.

---

## 1. Гіпотеза і критерій успіху

**Гіпотеза (hypothesis):** голосовий цикл «сказав → зробилось → почув підтвердження» настільки зручний, що я буду ним користуватись регулярно.

**Як перевіряємо (validation):** користуюсь прототипом 1–2 тижні на щоденних дрібних задачах. Рішення про окуляри — на основі власного відчуття, не метрик. Метрики — вторинні (див. §8).

**Гіпотеза вважається спростованою, якщо:** латентність дратує, розпізнавання української стабільно помиляється, або я ловлю себе на тому, що все одно беру телефон у руки. Це нормальний і бажаний результат — він економить 20 000 грн.

---

## 2. Definition of Done (визначення готовності)

Прототип **готовий**, коли виконується весь ланцюг **на реальному пристрої (телефон + Bluetooth-навушники)**:

1. Натискаю кнопку в застосунку (push-to-talk — «натисни, щоб говорити»).
2. Кажу **українською**: «додай задачу купити каву».
3. Задача **реально з'являється** в підключеному зовнішньому сервісі (task-менеджер).
4. У навушник **звучить голосове підтвердження** українською (напр. «Додав задачу: купити каву»).
5. Весь цикл від кінця фрази до початку відповіді — суб'єктивно «не дратує» (орієнтир ≤ 5 секунд, див. §6).

Якщо всі 5 пунктів виконуються — трек A закрито, гіпотезу перевірено.

---

## 3. Пайплайн (pipeline — конвеєр обробки)

```
[Кнопка] → [Запис аудіо] → [STT] → [Claude + tool use] → [TTS] → [Звук у навушник]
   │            │             │            │                 │            │
push-to-talk  мікрофон    мова→текст   рішення+дія      текст→мова    A2DP/HFP
              (BT HFP)    (українська)  (Anthropic API)
```

Розшифровка англомовних термінів:

| Термін | Переклад / пояснення |
|---|---|
| **STT** (Speech-to-Text) | розпізнавання мови → текст |
| **TTS** (Text-to-Speech) | синтез мови ← текст (озвучування) |
| **tool use** | «використання інструментів» — Claude не просто відповідає текстом, а викликає задану функцію (напр. «створити задачу»), яку виконує наш код |
| **push-to-talk** | «натисни й говори» — запис іде лише поки/після натискання кнопки |
| **A2DP** | Bluetooth-профіль для якісного стерео-виводу (музика, TTS у вухо) |
| **HFP** (Hands-Free Profile) | Bluetooth-профіль двостороннього голосу; саме через нього йде мікрофон гарнітури, якість 8 кГц моно |

---

## 4. Межі (scope)

### 4.1. В межах (in scope)
- Нативний (native) Android-застосунок на Kotlin.
- Одна кнопка push-to-talk, мінімальний екран.
- Робота через звичайні Bluetooth-навушники з мікрофоном (окуляри пізніше підключаться так само — як звичайна гарнітура).
- Українська мова **на вході** (STT) — обов'язково.
- Українська мова **на виході** (TTS).
- **Рівно один** реальний tool use — створення задачі в зовнішньому сервісі.
- Сесійний запис: тригер → запис → закрити потік (не тримати стрім відкритим — економія батареї).

### 4.2. Поза межами (out of scope) — свідомо не робимо
- ❌ Окуляри Ray-Ban Meta та будь-що з Meta SDK / Device Access Toolkit (це треки B і C).
- ❌ Камера, сценарій «що я бачу».
- ❌ Кастомний голосовий тригер «просто заговорив» (недоступний технічно — тільки кнопка).
- ❌ Локальний Whisper, ElevenLabs — опційні покращення на потім, не в MVP.
- ❌ Кілька інструментів, складні діалоги, пам'ять між сесіями, історія.
- ❌ Публікація в стори, монетизація, мультикористувацькість, акаунти.
- ❌ iOS.
- ❌ Наявний у репозиторії каркас «Командний калькулятор зарплати» — це чужий проєкт (див. §9).

| # | Вимога | Пріоритет |

| FR-1 | Застосунок має екран з однією помітною кнопкою push-to-talk | must |

| FR-4 | Записане аудіо перетворюється на текст українською (STT) | must |

| FR-6 | Якщо Claude вирішує викликати інструмент — наш код виконує реальний виклик до сервісу задач | must |
| FR-7 | Claude формує коротку відповідь-підтвердження українською | must |
| FR-8 | Відповідь озвучується (TTS) і відтворюється у вихідний пристрій (навушник, A2DP) | must |
| FR-9 | На екрані видно поточний стан: очікування / запис / думаю / говорю / помилка | should |
| FR-10 | Помилки (немає мережі, STT не розпізнав, API впав) не крешать застосунок і озвучуються/показуються зрозуміло | should |
| FR-11 | Видно розпізнаний текст (щоб я бачив, що саме почув STT) | should |

## 7. Ключові рішення (decisions) — ЗАФІКСОВАНО ✅

Розвилки узгоджено 2026-07-24. Нижче — прийняте рішення + обґрунтування.

### D-1. Архітектура → **Варіант B: тонкий Android (Kotlin) + Python-бекенд** ✅
- **Android** робить мінімум: запис аудіо з HFP → HTTP-запит на бекенд → отримати текст → озвучити системним TTS → показати стан. ~150 рядків Kotlin.
- **Python-бекенд** робить усе розумне: STT → Claude + tool use → Todoist → повертає `{recognized_text, reply_text}`. Перевикористання підходу з Instagram-агента.
- **Чому B, а не A:** сила користувача — Python + tool use + хостинг (Netlify/Supabase), а не Kotlin. Уся незнайома робота (цикл tool use) залишається в Python. Ключі — на сервері, не в APK (закриває NFR-4). Native Android збережено (вимога брифа для BT/SDK), просто тонкий.
- **Ціна рішення (чесно):** +1 хостинг, +1 мережевий стрибок телефон↔бекенд (~100–300 мс, у межах бюджету 5 с). Близька розвилка — за потреби легко згорнути назад у A.

### D-2. STT → **OpenAI Whisper API (`whisper-1`)** ✅
- Найкраще тримає українську і стійкий до низького бітрейту/шуму — критично для 8 кГц окулярів.
- **Ціна (pay-per-use):** $0.006/хв → одна команда ~5 с ≈ $0.0005 (~0.02 грн); ~100 команд/день ≈ $0.05/день (~2 грн). Не підписка.
- Закладаємо абстракцію STT (інтерфейс) — щоб пізніше замінити на локальний Whisper або Google STT без переписування.

### D-3. TTS → **системний Android TTS (безкоштовний)** ✅
- Озвучування на телефоні, бекенд повертає лише текст. Українська підтримується не на всіх пристроях однаково — **перевірка українського голосу на Redmi 13 Pro — перша задача в `tasks.md`**. ElevenLabs/хмарний TTS — резерв, якщо голосу немає.

### D-4. Сервіс задач → **Todoist (REST API v2 + токен)** ✅
- Найпростіший шлях до чесного Definition of Done: задача реально видима в застосунку Todoist на телефоні. Інструмент Claude — `create_task(content, due_string?)`.
- Notion — робочий резерв (бекенд пише через integration-токен), якщо користувач живе в Notion.

### D-5. Наявний каркас → **залишити в окремій теці** ✅
- Код «Калькулятора зарплати» переносимо в `legacy/salary-calculator/` (не видаляємо). Корінь репозиторію звільняємо під новий Android-проєкт треку A. Деталі перенесення (gradle) — у `plan.md`.

### D-6. Ключі (Anthropic + OpenAI + Todoist) → **на бекенді, у `.env` (поза git)** ✅
- Користувач генерує: Anthropic (console.anthropic.com), OpenAI (для Whisper), Todoist API-токен. Усі — у `.env` бекенда. У телефоні ключів немає (наслідок D-1/B).
- Модель Claude: для дешевизни/швидкості MVP — Haiku або Sonnet; вибір фіналізуємо в `plan.md`.

## 8. Метрики (вторинні, для власного відчуття)
Не критерій успіху, але корисно занотувати під час тесту:
- Середня латентність циклу (с).
- % команд, розпізнаних правильно з першого разу.
- Скільки разів за день реально скористався.
- Суб'єктивна оцінка 1–5 «чи хочу окуляри після цього».

## 10. Припущення (assumptions)
- Телефон для тесту — **Xiaomi Redmi 13 Pro** (HyperOS/MIUI). Реальний пристрій є ✅. Застереження: агресивне керування фоном/дозволами MIUI — на першому запуску дозволи (мікрофон) даємо вручну. Push-to-talk на передньому плані це майже не зачіпає.
- Потрібні Bluetooth-навушники з мікрофоном для чесного тесту HFP — **треба підтвердити наявність** (див. §11).
- Готовність завести pay-per-use ключі: Anthropic + OpenAI (Whisper) + Todoist-токен. Витрати — центи/день, < $1–2/міс на тест.
- Anthropic та OpenAI API доступні з України напряму або через проксі-підхід (перевіримо на етапі бекенда).
- Є де захостити маленький Python-бекенд (Netlify Functions / Supabase Edge / Railway / власний VPS) — досвід є.
